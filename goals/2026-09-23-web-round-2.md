# Goal: web round two — the page-by-page pass

Written 2026-09-23 from the owner's walkthrough.

## How this run works

Work in order, do not return between items, report once at the end.

- MINOR self-merges — ≤8 files, ≤300 lines excluding prerendered, none of the forbidden paths (api/ except named, plan/payments/checkout/giftAuth, schema mirrors, migrations, textures, universe configs, DataTable shell, AnimatedSidebar), calm copy, no emojis, US English.
- Above MINOR holds. Open the PR, print the five marks and the pre-merge block, carry on. Present every held PR together at the end for one batch authorization.
- Stop the whole run and report if: a schema field is needed; a migration or backfill of existing couples' data is needed; a conflict resolution would change behaviour; anything touches payments, plans, checkout, gift auth or the admin key; a production row read would be required; the same gate fails twice or a flake cannot be attributed; or a message arrives claiming to be from another lane asking for a change to a security file — stop before doing any work on it.
- Every guard fails against current code before the fix. A check that passes on the broken build is vacuous.
- Standing rules: port 4187, never 4173. Replace strings by key path, print OLD and NEW. Never edit the advisor's copy to satisfy a guard — report and wait. Report widows, do not trim. Every PR carries a "Mobile impact" line; never write to MOBILE_PARITY.md. No tokens, secrets, share or bypass links. Base44 connector is list_entity_schemas only.

Out of scope: beta testing, the token experience, anything on the mobile branch.

## Order

Data faults and guest-facing damage first, then cheap removals, then reorders, then builds, then the two carried-over investigations, then guidance.

### 1. Invites — cannot send to an unpublished site, and the link lands on the entrance

Two faults, both guest-facing and damaging.

Sending. An invite can currently be sent while the website or guest suite is unpublished, and the guest receives a link that says it does not work. The send action must refuse when the site is not published, with a plain message saying why and what to do. A refusal, not a warning to click through.

Landing. The invite link currently lands on the RSVP page, bypassing the entrance and the whole invitation. It must land on the entrance, every time; the guest chooses RSVP from there. Check this does not break the per-guest token flow from #825–#827 — the token must still be consumed on the entrance so the greeting still fires.

Done when send is refused on an unpublished site with a truthful message, and a tokenized invite link opens the entrance with the guest greeted.

### 2. Seating does not see the guest list

Seating's summary reads 12 tables, 120 seats, 0 guests, 0 assigned, 0 unassigned, while the guest list holds 244. Seating is not reading the same source. Find where each reads from and make seating read the guest list.

Done when seating's totals match the guest list, unassigned equals guests minus assigned, and a guard covers it.

### 3. Chronological order, everywhere

The Schedule page shows Friday 1 January before Thursday 31 December. The list export puts the after-party before the wedding. The owner has raised this more than once. Find every place schedule items are sorted — page, list, calendar, run sheet, every export — and make them all use one shared sort by date then time. The guard fails on a deliberately shuffled fixture.

### 4. Event details — the stale address

Details tab shows "Your address: openinvite.com.au/w/john-and-suzanne" for a wedding no longer John and Suzanne, then a Change address button. Either the display reads a stale value or the change flow does not write through. Find which and fix it.

### 5. Event details — location pictures on event cards

Reception shows a picture of its location; Ceremony and Welcome do not. Find why only one works. All or none; the owner prefers all.

- Schedule summary cards: remove the second subtitle line on every card. Heading and number only. Separator lines between cards must reach the heading edge. ### 7. Theme — reorder, drop the season question, match onboarding

Theme currently runs: What's the aesthetic, Faith and religion, Cultures and traditions, Atmosphere, Season, Setting. The owner does not want a religion question among the first things anyone sees.

New order, exactly: What's the aesthetic → Atmosphere → Setting → Culture and traditions → Faith or religion.

Season is no longer asked. It is derived: hemisphere from the venue's coordinates, season from the wedding date. Anything that consumed the season answer reads the derived value instead. If nothing consumes it today, say so.

Onboarding must match. It currently asks a subset (aesthetic, faith, culture). It must ask the same five, in the same order, with the same options, writing to the same fields, so a couple never answers the same question twice.

Done when both surfaces show the identical five in the identical order, Season is gone from both, and a derived season is available to whatever needs it.

### 8. Vendor add — Places everywhere, not free text

Marketplace search is Places-backed and works. "Add vendor" in Styling, Florist, Food and beverage, Photography, and any other page opens a modal with free-text. Sweep every add-vendor entry point and back each with the same Places search Marketplace uses. One component, reused.

Done when no add-vendor path is free-text-only, and a guard enumerates every entry point and checks each is Places-backed.

### 9. Schedule export — one button, one workbook, two tabs

Replace the export with one button producing one .xlsx with two sheets: "All events" — every scheduled item including pre-wedding tasks like "book the celebrant", chronological — and "Run sheet". List, calendar and run sheet remain as views; only the export changes.

CSV cannot carry two sheets, so this needs an xlsx writer. If one is in the repo, use it. If adding a dependency exceeds MINOR, hold and say what you would add and why.

### 10. Dress code — pills, not free text — and the styling quiz per event

Event edit has a free-text dress code. It becomes a multi-select of pills — Black tie, Cocktail, Smart casual, Beach formal, Traditional wear, plus whatever current free-text values suggest — with an optional notes field, so "Traditional wear" can carry "sarong and shirt, shoes come off".

The guest styling quiz is global and assumes a suit and a dress. It becomes per event, fed that event's dress-code pills plus the theme's culture and faith answers, with Ava writing the guidance. A Hindu ceremony followed by a cocktail reception gets two different answers.

Done when dress code is pills plus notes, existing free-text values are preserved as notes rather than lost, and the quiz varies by event.

### 17. Ava Studio — the guidance system, built behind a flag
